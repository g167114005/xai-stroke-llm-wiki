# Graph：主題 → HTML 簡報

輸入：一個主題。輸出：一份只用 wiki 內容做成的 HTML 簡報，附檢查報告。
流程是事先畫好的；AI 不能跳關，錯在哪一關就退回哪一關。

```
 ① 檢索 wiki ──▶ ② 覆蓋率關卡 ──▶ ③ 證據卡（平行）──▶ ④ 大綱 ──▶ ⑤ 人工確認
                    │ 不足                                  ▲          │ 退回
                    ▼                                       └──────────┘（修大綱；缺題 → 回 ①）
                   停下

 ⑥ 逐頁稿 ──▶ ⑦ 忠實度檢查 ──▶ ⑧ 渲染 HTML ──▶ ⑨ 渲染檢查 ──▶ ⑩ 交件
     ▲  ▲          │ 退回：只修那一頁                    │ 退回：字太多
     │  └──────────┘                                     │
     └───────────────────────────────────────────────────┘（回 ⑥ 縮短，不在 ⑧ 硬塞）
              ⑦ 若錯在證據卡本身 → 退回 ③ 重抽那一張卡
```

## 每一關：輸入、輸出、怎麼檢查

| # | 節點 | 類型 | 輸入 | 輸出檔案 | 檢查方式 | 沒過時 |
|---|---|---|---|---|---|---|
| ① | 檢索 wiki | AI | 主題、`wiki/index.md` | `01_retrieval.md` | — | — |
| ② | 覆蓋率關卡 | 程式 | `01_retrieval.md` | `02_coverage.md` | 相關議題頁 ≥ 3、相關論文頁 ≥ 3、每個議題頁至少一條帶出處的證據 | **停下**，回報缺什麼；不用常識硬湊 |
| ③ | 證據卡 | 程式抽取 | 一張卡只看**一個** wiki 頁 | `03_cards/<頁名>.md` | 每條 claim 都有出處；wiki 本身已通過 lint | 重抽那一張 |
| ④ | 大綱 | AI | 全部證據卡 | `04_outline.md` | 8–15 頁；每頁列出用到哪些卡 | — |
| ⑤ | 人工確認 | 人 | `04_outline.md` | 確認紀錄寫回 `04_outline.md` | 人看過、說可以 | 退回 ④；若缺主題 → 退回 ① |
| ⑥ | 逐頁稿 | AI | 大綱＋該頁對應的卡 | `05_drafts.json` | 內圈 loop：寫一頁 → 檢查出處 → 修，最多 2 輪。每個要點都要帶 claim 代號；白話比喻只能取自觀念頁的「白話解釋」，而且不可含數字 | — |
| ⑦ | 忠實度檢查 | 程式＋AI 審查 | 逐頁稿＋證據卡＋`raw/` | `06_faithfulness.md` | 程式：每個要點有 claim 代號、數字在 claim 裡找得到、出處在 `raw/` 回查得到。AI 審查：新對話、只給成品與來源，查有沒有講反、有沒有漏 | 只修被點名的那一頁（回 ⑥）；卡本身錯 → 回 ③ |
| ⑧ | 渲染 HTML | 程式 | 已通過的逐頁稿 | `slides/index.html` | — | — |
| ⑨ | 渲染檢查 | 程式 | HTML | `08_render_check.md`＋截圖 | 無頭瀏覽器逐頁量測：內容不可超出 1280×720 的版面；同時只能顯示一頁 | 字太多 → 退回 ⑥ 縮短；樣式問題 → 退回 ⑧（不改文字，不必重跑 ⑦） |
| ⑩ | 交件 | — | — | 簡報＋兩份檢查報告 | — | — |

## 每一關只能看什麼、不能做什麼

| 節點 | 只能看 | 不能做 |
|---|---|---|
| ③ 證據卡 | 一個 wiki 頁 | 混入其他頁或 wiki 以外的內容；改寫數字 |
| ④ 大綱 | 證據卡 | 回頭讀 `raw/` 找新材料（缺材料要退回 ①） |
| ⑥ 逐頁稿 | 大綱＋該頁對應的卡 | 引用卡片以外的內容；新增卡片上沒有的數字 |
| ⑧ 渲染 | 已通過的逐頁稿 | 改任何一個字（排版放不下就退回 ⑥） |
| ⑦⑨ 檢查關卡 | 成品＋來源 | 自己動手改成品 |

## 剎車
- ⑥ 內圈最多 2 輪；⑥→⑦、⑥→⑨ 的退回合計最多 3 輪，超過就停下來交給人。
- ② 不足就停，不開始。
- 大圈（從 ⑨ 退回 ①）應該很少發生；如果常常發生，代表檢查該往前移。

## 為什麼用 Graph 而不是一個 Loop
- 各階段的「完成標準」不同：證據卡看的是忠於來源，逐頁稿看的是忠於卡片，渲染看的是版面。用一個 loop 會每次整份重來。
- 錯誤要在離源頭最近的地方被抓到：數字錯在 wiki 就由 lint 抓；錯在抄寫就由 ⑦ 抓；版面問題才到 ⑨。
- 要有人工確認的關卡（⑤），而且只放一個，放在「改起來最便宜」的大綱階段。

## 怎麼執行
```
python tools/cards.py workflow/run-01 <wiki 頁名…>      # ③
python tools/slides_check.py workflow/run-01            # ⑦ 程式部分
python tools/render_slides.py workflow/run-01           # ⑧
node tools/render_check.js workflow/run-01              # ⑨
```
①④⑥ 與 ⑦ 的 AI 審查由 coding agent 依本檔執行；⑦ 的審查 prompt 在 `workflow/prompts/reviewer.md`。
