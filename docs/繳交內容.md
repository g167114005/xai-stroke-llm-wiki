## 1. LLM Wiki 主題與簡短介紹
主題是「可解釋 AI（SHAP、Grad-CAM）用在急性缺血性中風神經影像」。來源是我自己即將刊出的一篇 critical review，加上它引用的 31 篇論文全文，共 32 份。

建法是「先討論、後生成」：AI 先問了八題（讀者是誰、要哪些頁面、語言、出處多細、論文矛盾怎麼辦、一次幾篇、之後產出什麼、lint 檢查什麼），整理成需求摘要給我確認，才寫 AGENTS.md 並開始 ingest。我的回答直接變成規則，例如：
- 讀者是沒有醫療背景的同學與老師，所以每個論文頁開頭有一句不帶術語的說明，另有觀念頁解釋名詞。
- 每個數字都要標到 PDF 頁碼，而且 lint 會拿數字去對那一頁的文字，找不到就不給過。
- 原文與我們的 review 不一致時以 review 為準，但要標記並集中列在一頁。

成果：53 頁（論文頁 32、觀念頁 9、議題頁 7、比較頁 3、目錄與紀錄），370 個出處、384 個數字全部回查得到。

## 4. Graph 的設計
我用 Graph。流程圖與每一關的規格：https://github.com/g167114005/xai-stroke-llm-wiki/blob/main/workflow/GRAPH.md

① 檢索 wiki → ② 覆蓋率關卡 → ③ 證據卡 → ④ 大綱 → ⑤ 人工確認 → ⑥ 逐頁稿 → ⑦ 忠實度檢查 → ⑧ 渲染 HTML → ⑨ 渲染檢查 → ⑩ 交件

- 資訊怎麼取得：① 從 wiki 目錄找相關的議題頁、論文頁、觀念頁；② 用程式確認材料夠不夠，不夠就停下，不用常識硬湊。
- 怎麼整理：③ 一張證據卡只看一個 wiki 頁，把帶出處的句子原樣抽出來編號；④ 依卡片排大綱；⑥ 逐頁稿只能用卡片上的句子，每個要點都要標卡片代號。
- 怎麼檢查：⑦ 程式檢查數字是否在所引卡片裡，再由 AI 檢查有沒有講反或誇大；⑨ 用無頭瀏覽器逐頁量版面。
- 哪些步驟會重複：⑥ 內部是小 loop（寫一頁 → 檢查出處 → 修，最多 2 輪）；⑦ 沒過只退回 ⑥ 修被點名的那一頁；⑨ 沒過時，字太多退回 ⑥、樣式問題退回 ⑧；④ 缺材料退回 ①。退回合計最多 3 輪，超過就交給人。
- 為什麼這樣設計：每個階段的完成標準不同（卡片要忠於 wiki、稿子要忠於卡片、渲染要版面不溢出），用一個 loop 會每次整份重來；Graph 可以錯在哪一關就退回哪一關。人工確認只放一關，放在改起來最便宜的大綱。

## 6. 反思
**哪一個節點最常出錯？**
被退回最多的是 ⑥ 逐頁稿與 ⑧ 渲染，各兩次。⑥ 的錯是「寫的人順手加了卡片上沒有的東西」：一個沒出處的數字、一句自己的評語、一個講得太滿的詞。⑧ 的錯是樣式，而且第一次很嚴重：最後一頁的版型名稱與流程圖的樣式同名，結果它蓋住了所有頁。

**發現問題後，把檢查往前移到哪一步？**
1. 渲染檢查腳本第一輪只報 1 頁不合格，是我打開截圖才發現 13 張全是同一頁。腳本只量「目前這一頁」的尺寸，所以量不出來。我把「同時只能顯示一頁」加進 ⑨ 的腳本，以後不靠人看截圖。
2. 數字的檢查其實早在建 wiki 時就做了：lint 在 ingest 階段就把每個數字對回 PDF 頁面。所以到了簡報階段，⑦ 只需要檢查「稿子對不對得上卡片」，不必再回頭翻論文。這是整個流程裡最有用的一次「往前移」。
3. 檢查工具自己也會錯：lint 一開始把空白全刪掉，「0.86, 95%」黏成「0.8695」，把對的數字判成錯的。修正後留了獨立的 commit。

**有沒有因此修改 workflow / graph？**
有，三處：
- ⑨ 多一條退回路線。原本只寫「沒過就退回 ⑥ 縮短文字」，但實際的原因是樣式不是字數，所以改成：字太多 → ⑥；樣式問題 → ⑧（不改文字，不必重跑 ⑦）。
- ⑨ 多一項檢查（同時只能顯示一頁）。
- ⑥ 多一條規定：白話比喻只能取自觀念頁的「白話解釋」，而且不可含數字。

**沒做到的地方**
- ⑦ 的 AI 審查應該開新的對話、只給成品和來源。這次是同一個對話裡的 AI 自己審，等於叫它審自己的作品。審查用的 prompt 留在 repo 裡，可以補跑。
- 32 篇不是每一頁都精讀：AI 讀的是摘要頁加上對關鍵詞的逐頁檢索。數字都有回查，但 Methods 的細節沒收進來。

**意外的收穫**
「以 review 為準」這條規則讓 wiki 抓到我自己論文裡一個要核對的數字（某篇研究的 AUC，我們寫 0.791，原文摘要寫 0.793）。稿子還在校樣階段，來得及確認。
