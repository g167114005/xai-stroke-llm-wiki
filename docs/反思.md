# 反思（草稿）

> 這份是 AI 依實際過程起草的，事實都對得到專案裡的檔案；語氣與取捨請改成自己的話再交。

## 1. 建 Wiki 時特別考量的事情

**先討論、後生成，差在「規則是我的，不是模型猜的」。**
上週一句話生成的 AGENTS.md 是 Karpathy 範本的通用版。這週 AI 先問了八題，我的回答直接變成規則：讀者是沒有醫療背景的同學與老師，所以每個論文頁開頭都有一句不帶術語的說明，另外有一頁專門解釋 NIHSS、mRS、取栓這些名詞；出處要到頁碼；四種頁面類型都要。逐條對照表在 `docs/02_需求摘要.md`。

**最花心思的是「以我們的 review 為準」這條規則。**
我的主題是自己即將發表的 critical review 和它引用的 31 篇文獻。兩邊說法不一致時，我選擇以 review 為準。AI 在訪談時就提醒：review 自己也是來源，這等於自己當裁判。所以我們加了兩個保護：論文頁把「原文怎麼說」和「review 怎麼評」分成兩節；所有不一致集中登記在一頁（`wiki/issues/review-vs-original.md`）。結果真的抓到一筆：Huang H. et al. 的位置模型 AUC，review 寫 0.791，原文摘要寫 0.793（原文表格裡兩個數字都有，分屬不同演算法）。這對我是實際的收穫，因為稿子還在校樣階段，來得及回頭核對。

**「數字可回查」讓我敢相信這個 wiki。**
lint 會把 wiki 每一行的數字拿去對所標的 PDF 頁面，找不到就不給過。最後是 53 頁、370 個出處、384 個數字全部對得上。過程中也發現檢查工具自己會錯：lint 一開始把空白全刪掉，結果「0.86, 95%」黏成「0.8695」，把正確的數字判成找不到。所以「腳本說了算」的前提是腳本也要被檢查，這個修正我留了一個獨立的 commit。

**其他取捨。**
- review 是 .docx 校樣，頁碼會跟著排版變，所以改標章節（§4.1）。
- `raw/` 有尚未刊出的校樣和有版權的 PDF，所以不進版控、不推上 GitHub，只用 `sources.csv` 記錄來源清單。
- review 和 core 8 篇是一篇一個 commit，其餘 23 篇分三批。批次比較快，但 commit 紀錄就看不出每一篇改了什麼。
- 誠實地說，32 篇並不是每一頁都精讀：AI 讀的是摘要頁加上對關鍵詞的逐頁檢索。數字都有回查，但 Methods 的細節沒有收進來。這寫在 `wiki/log.md` 的已知限制裡。

## 2. Graph 的設計

**為什麼用 Graph 不用 Loop。**
「主題 → 簡報」的每個階段，完成標準都不一樣：證據卡要忠於 wiki，逐頁稿要忠於證據卡，渲染要版面不溢出。用一個 loop 的話，任何一處出錯都要整份重來。Graph 可以做到「錯在哪一關，就退回哪一關」。規格在 `workflow/GRAPH.md`。

**十個節點。**
檢索 → 覆蓋率關卡 → 證據卡 → 大綱 → 人工確認 → 逐頁稿 → 忠實度檢查 → 渲染 → 渲染檢查 → 交件。

**我特別設計的三件事。**
1. *每一關只能看什麼。* 證據卡一張只看一個 wiki 頁；逐頁稿只能用卡片上的句子，每個要點都要標卡片代號（例如 `議題5·C7`）；渲染那一關一個字都不能改。這樣簡報上任何一句話，都能從卡片追到 wiki，再追到 PDF 的頁碼。
2. *人只確認一次，放在最便宜的地方。* 我只在大綱那一關看了一次，要求加一頁「這份簡報怎麼做的」，這時候改只是多一列。
3. *檢查分成程式和 AI 兩種。* 數字對不對交給腳本；有沒有講反、有沒有誇大交給 AI 審查。

**實際跑起來的退回（都有紀錄）。**
- ④ → ①：排大綱時發現「為什麼需要解釋」那一頁沒有材料，退回補檢索兩個觀念頁。
- ⑦ → ⑥ 兩次：腳本抓到第 4 頁圖上的「30」不在所引的卡片裡；AI 審查抓到第 2 頁有一句沒出處的評語、第 12 頁把「幾乎沒被驗證」寫成「沒被驗證」。每次都只修被點名的那一頁。
- ⑨ → ⑧ 兩次：第一輪腳本說只有 1 頁不合格，但打開截圖，13 張全是同一頁（樣式名稱衝突，最後一頁蓋住了所有頁）。腳本只量「目前這一頁」所以沒發現。修完之後，我們把「同時只能顯示一頁」加進腳本。這正是課堂說的：常常要靠後面才抓到的錯，代表檢查該往前移。

**沒做到的地方。**
AI 審查應該開新的對話、只給成品和來源。這次是同一個對話裡的 AI 自己審，等於「叫它審自己的作品」。我把審查用的 prompt 留在 `workflow/prompts/reviewer.md`，之後可以在新對話補跑。

## 3. 其他心得

- **規格比 prompt 重要。** 這次我幾乎沒有寫「請做好一點」這種話，寫的都是「怎樣算做完」：lint 全過、每個要點有卡片代號、13 頁都不溢出。
- **檢查會抓到我自己的東西。** 原本只是交作業，結果 wiki 順便幫我校對了自己的論文。
- **AI 會誠實到什麼程度，取決於我有沒有要求它留紀錄。** 退回幾次、哪裡沒做到，都是因為流程規定要寫報告才留下來。
- **成本。** 32 篇加上一份簡報，中間產物很多（53 頁 wiki、19 張證據卡、三份檢查報告）。如果只是要一份簡報，一句 prompt 快很多；但我要的是之後寫論文還能用、而且每個數字都查得到的東西，這個結構才划算。
- **下次會改的。** 先 ingest 5 篇把規則磨好，再批次處理其餘的；AI 審查一開始就排成獨立的對話。
